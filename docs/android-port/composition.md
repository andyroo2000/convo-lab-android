# Immediate Japanese composition

The Kotlin composition model ports the stable iOS Journal input behavior at `6dae16a`. It converts romaji synchronously without waiting for neural inference. Suggestions cannot change a document until the writer explicitly chooses one. Revision identifiers reject stale results; UTF-16 selection, emoji, paste, deletion inside combined kana, section resizing, and context after partial acceptance have dedicated coverage.

The WanaKana 5.3.1 MIT tables are generated by `scripts/generate_romaji.mjs` from a verified package source digest. `scripts/generate_composition_fixtures.mjs` records five behavioral scenarios directly from the iOS JavaScript state machine. JVM tests cover those scenarios and 1,538 transliteration cases. The Android contract test verifies the packaged tables and measures immediate state updates independently of rendering and inference.

Pixel 10a results: p95 0.60 ms, maximum 24.95 ms, table warm-up 45.80 ms. This is a small public-fixture microbenchmark, not end-to-end typing latency. The model and tables should be warmed before offering built-in input. Both Pixel and API 36 emulator contract tests pass. Build, lint, and 115 JVM tests pass.

This change provides the state model; the candidate dock, keyboard chooser, account-owned inference, and learning settings are separate integration work tracked in #13.
